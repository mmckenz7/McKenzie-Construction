# Fence commercialization — first operator path

Plan date: 2026-09-01

## Outcome

The shortest responsible path is one supervised outside field session on the immediate operator's actual fence system, followed by one independently reviewed estimate. Do not wait for tenant profile administration, automatic address search, or production map integration. Do not call a profile active until its exact rules and one representative sample job pass independent review.

## System selection

**System 1** is the exact manufacturer, product family, style, height, gate configuration, and installation method the immediate real operator will use. It is not selected until Michael supplies those facts. If it matches a current draft, create a reviewed version and change only facts supported by the supplied rule source. Otherwise run geometry-only until the closed profile union represents the documented rules.

After System 1 passes, choose a real, materially different **System 2**. A stick-built privacy system after manufactured panels is preferred when a real job and verified rules exist. Do not invent a second profile. If both systems pass without changing the generic evaluator architecture, later systems should normally be reviewed configuration/data rule packs.

## Activation ladder

1. Map every supplied rule to a closed profile field; missing or unsupported facts remain blockers.
2. Record the draft profile ID, version, content hash, rule source, author, and independent reviewer.
3. Compare one independently measured sample job against a separately completed human takeoff.
4. Resolve every difference as a rule correction, field-measurement correction, or unsupported-engine blocker.
5. Michael and the reviewer accept one exact profile hash for the bounded beta. A later rule change creates a new version.
6. Manually map only an accepted takeoff to reviewed catalog/labor items and current pricing. A second person reviews the estimate before customer delivery.

Current `draft_unvalidated` bundles are comparison aids, never ordering, pricing, or construction authority.

## Outside operator packet and session

Before the appointment provide the exact protected Preview URL/commit, a pre-travel sign-in check, `FIRST_FIELD_TRIAL_WORKSHEET.md`, approved tape/wheel/laser hardware, an independent backup sketch, the System 1 rule source and profile review sheet when takeoff is in scope, a stop-and-call instruction, and screenshot deidentification rules.

The supervisor retains profile/deployment identity, the independent takeoff, and the outcome. The operator does not edit profile source or waive discrepancies.

1. Confirm deployment and sign-in.
2. Sketch and label physical runs independently.
3. Enter exact measured geometry; imagery is context only.
4. Reconcile gates from physical Post A or Post B.
5. Compare every run, connection, gate, and total to the field sheet.
6. Save, reload, and retain deidentified plan/takeoff evidence.
7. Compare takeoff only when the exact profile is eligible.
8. Record pass, contained correction, or stop. Do not order or price from the prototype.

## Minimum gaps

For the first supervised session Michael must select System 1, name the operator and verifier, provide a measurable permitted job, and supply an independent takeoff if quantities will be evaluated. No new UI is required for a geometry-first session; source-reviewed typed profile editing is safer than broad tenant administration before two systems establish the fields.

A reviewed estimate additionally needs an accepted profile hash, catalog/labor mappings and units, current price basis, preserved geometry/takeoff/profile identity, and estimator review of scope, waste, labor, tax, markup, and presentation.

A responsible paid beta additionally needs isolated operator/company access, save/export/recovery beyond one browser, visible profile activation status, persisted measurement review/provenance, reviewed terms and support procedure, and named human approval for every estimate.

## Google decision

Google address search should wait. It reduces navigation friction but verifies none of geometry, property lines, system rules, takeoff, or pricing. The first operator can use the protected Preview and independent site records without making the Demo Key or Geocoding API a field dependency. Existing licensed map context may be used only as non-authoritative reference.
