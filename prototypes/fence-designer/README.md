# Fence Visual Measure

An isolated, local-only 2D fence measurement prototype.

```sh
npm install
npm run validate
npm run dev
```

Open the local URL, add the measured house when needed, choose **Draw**, then tap or click to place connected points. Draw continues from the latest open endpoint by default, or from an open endpoint selected in Edit. Choose **Separate line** to start a divider or secondary fence anywhere. **Quick layout** adds one exact run at a time with commands such as `south 20 ft`, `right 90, 40 ft`, `left 45, 12 ft`, or `straight 8 ft`. The plan shows a dashed preview before the run is applied. Use **Eyeball next point** for an unknown angle; the command card clears the plan for that tap and immediately returns with the new endpoint selected. Both input methods use the same integer-millimeter geometry, selection, gates, totals, and undo/redo history.

Quick layout is a deterministic fence command parser, not an AI assistant or CAD import. Its first precise run needs north, south, east, or west; later turns are relative to the preceding fence segment rather than the screen or grid. A bare exact length continues straight. Commands and their short session log are not serialized and make no network request. **Gate on last run** opens the existing exact gate editor for the fence run that enters the active endpoint; a deliberately selected fence run takes priority. Gate width and distance from its starting post therefore remain visually auditable. Escape closes Quick Layout and clears an unfinished command without changing the design.

Consumer-phone **Site Walk** remains implemented for research but is removed from the primary toolbar after real-world short-run testing produced errors far larger than a residential fence layout can tolerate. It is not part of the current recommended workflow. Future field capture should use explicitly entered tape/wheel/laser lengths or reviewed higher-accuracy hardware; the stored measurement model remains provider- and hardware-independent.

On a phone, Site Walk becomes a focused field view: the large GPS action, separate-line action, one clearly labeled end action, zoom controls, visible status, and plan remain while the header, materials, property tools, selection inspector, and footer move out of the way. Portrait and landscape layouts keep the mark action thumb-sized and preserve a useful plan viewport. Start on an HTTPS deployment because mobile browsers generally require a secure page for location access. Stand still at each point and tap the mark action once. The app samples fresh high-accuracy positions for up to 20 seconds, shows the best reported radius live, finishes early at 5 meters (about 16 feet) or better, and rejects a result worse than 15 meters (about 49 feet). During acquisition the mark action becomes a visible countdown and remains tappable as **Cancel GPS lock**; canceling or leaving Site Walk clears Safari's active location watch without adding a point. After the starting fix, the app also ignores repeated cached iPhone coordinates until the phone reports actual movement or shows an actionable retry message. Each new raw GPS leg is applied from the latest corrected plan endpoint rather than the original origin, so exact length corrections cannot accumulate into the next run. Optional **90° corners** mode uses GPS only to choose the rough turn direction, squares the leg to the previous run, and requires its exact tape/wheel/laser length before enabling the next mark. These thresholds make poor phone data visible and prevent a clearly unusable fix from changing the plan; they do not make consumer GPS authoritative for short runs.

While drawing, the changing run length stays in a fixed on-canvas measurement box so it does not cover the target or reference image. After placement, completed dimensions render beside their fence runs with leaders, automatically separate from nearby labels, stay inside the visible plan, avoid unrelated runs when space allows, and remain a stable visual size while zooming. A selected span provides **Flip dimension side** for tight layouts plus **Auto-position dimension** to return it to automatic placement.

**Property** provides free/manual reference links for Acres, KGIS, and Google Maps. On desktop, open the permitted Acres or KGIS view and use **Capture map tab**, or copy a screenshot and use **Paste image**; no screenshot file needs to be managed. PNG, JPEG, and WebP upload remains a fallback. The captured image is compressed to a maximum 2,000-pixel edge, can be positioned, rotated, faded, locked, and scaled by entering a known distance and tapping its two endpoints. Before fence points are drawn, **Trace 4 house corners** uses the first traced wall as the horizontal reference, rotates only the local reference image, and creates an axis-aligned measured house footprint from the four marked corners. Automatic building detection remains deferred until real Acres/KGIS captures prove it can be trustworthy. Reference image, grid, house, and dimension visibility are independent. **Save local** stores the reference separately from the fence design in this browser only. It is excluded from fence history and totals and never replaces field measurements.

The Property panel also contains a disabled-until-configured **Live map beta** candidate. It uses only Google Maps JavaScript satellite/hybrid display, projects the canonical integer-millimeter Fence design into WGS84 without storing provider objects, accepts a permitted local GeoJSON/KML parcel overlay, and can show browser location plus its accuracy circle as an observation. Map taps and point drags route back through the existing Fence model only when sketching is explicitly enabled. Export is a local GeoJSON/KML file and remains disabled until the user deliberately places the plan on the map; it is not Acres/LandGlide synchronization. No geocoding, Places, Street View, provider persistence, or live KGIS access is included. The browser key is runtime-only and must never be committed.

Free angle is the default. After the first run, optional 45°/90° assistance uses the previous segment's bearing as its reference, so a straight continuation remains straight even when the whole fence is diagonal to the screen. The grid has its own always-available toolbar toggle and can be hidden without changing snapping, measurements, or saved geometry. Select a fence run where the gate should sit, choose **Add gate**, then enter its style, total width, and exact fence length from the selected run's starting post to the near side of the gate. Clicking the run supplies the initial distance. The gate replaces only that portion of the straight run and does not change its bearing or combined length; its exact location splits fence-panel rounding before and after the opening. Selecting the finished gate shows its distance from the previous post. The displayed total combines every perimeter, divider, and gate run. Applying an exact run length advances to the next authored span until the full line is reviewed. Saving uses only this browser's local storage.

**Export job** downloads a deterministic `.mckenzie-fence.json` file containing canonical geometry and gate intent. **Open job** validates and restores that file on another device without a network database. Reference imagery, map-provider data, pricing, customer data, and transient takeoff confirmation are deliberately excluded; an imported job must be reviewed and reconfirmed before takeoff. The file is capped at 2 MB and malformed or unsupported versions fail closed.

Canonical geometry also writes to a separate, browser-only crash-recovery slot after each revision. Refreshing the same browser restores that draft without treating it as a deliberate saved job or carrying reference imagery, takeoff confirmation, pricing, or provider state. **Save local** remains the explicit same-device design/reference save; **Export job** remains the portable copy.

**Materials** first requires **Confirm layout for takeoff**. Every fence type uses the same Draw, Edit, gate, closure, relative-angle, exact-length, and line-topology rules; material selection appears only for the confirmed drawing revision. Any later geometry edit returns Materials to confirmation before recalculating. The selected **Black Aluminum** or **Treated Pine Privacy** takeoff never changes the drawing. Treated Pine Privacy is 6 feet high with touching 6-inch 1×6×6 pickets, 8-foot maximum bays, three 2×4×8 rails per bay, treated 4×4 posts, one 50 lb concrete bag per installed hole, and 10% purchase waste on all lumber. A single gate uses five 2×4 frame pieces and two hinges; a double uses ten frame pieces, four hinges, one latch, and one drop rod. Gate pickets are included. Picket fasteners are six screws per installed picket—two at each of three rails. Preliminary structural fastening uses 12 rail-to-post screws per installed bay and 12 gate-frame screws per leaf. Hinge, latch, and drop-rod mounting fasteners are assumed included with those hardware items. The summary distinguishes installed quantity from the 10% lumber allowance, **Copy takeoff** produces the selected deterministic report, and **Print / save PDF** produces a control-free plan and confirmed takeoff packet. Both takeoffs remain session-only, preliminary, no-pricing derivations and are never saved into measurement geometry.
